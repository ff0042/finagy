# Project Rules & Guidelines for Finagy

## Feature Sandboxing & Branching Directive
Whenever a major feature, new version phase (e.g., V3 Multi-Account, V4 Options Desk), or architectural refactoring is requested:
1. **Detect Major Changes**: Identify if the request introduces a new feature area or version phase.
2. **Offer Sandboxing / Feature Branching**: Check current git branch and explicitly offer to create a dedicated feature branch (e.g., `feature/v3-multi-account-schwab`) or isolated workspace before modifying source code.
3. **Planning & Approval**: Present a structured `implementation_plan.md` artifact for user review before proceeding to execution.
